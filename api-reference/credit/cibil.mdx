CIBIL score retrieval is a critical step in the loan assessment workflow. Clikzop Bank EMI provides two paths to obtain CIBIL data for a loan: you can fetch a live credit report directly from the bureau via our CIBIL data provider, or upload an existing CIBIL PDF and let the platform extract and store the text content for downstream processing. Both methods store the result against the loan record and make it available to the eligibility engine.

---

## Fetch Live CIBIL Data

<ParamField path="POST /api/get-cibil-data" type="endpoint" />

Use this endpoint to pull a live CIBIL report for the applicant associated with a loan. The platform requests the bureau report via our CIBIL data provider, parses the full credit profile, and stores all account and enquiry records against the loan. The customer's PAN, mobile number, and name are automatically sourced from the loan's linked customer record — you only need to supply the `loan_id`.

<Note>
  The customer must already be linked to the loan via `save-loan` before calling this endpoint. The platform reads PAN, mobile, and name from the linked customer profile automatically.
</Note>

### Request

```bash
curl -X POST "https://your-domain.com/api/get-cibil-data" \
  -H "Authorization: Bearer {your_token}" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{
    "loan_id": 1
  }'
```

### Parameters

<ParamField body="loan_id" type="integer" required>
  The ID of the loan for which to fetch CIBIL data. The customer's PAN, mobile, and full name are resolved automatically from the linked customer record.
</ParamField>

### Response Fields

<ResponseField name="status" type="boolean">
  `true` on success.
</ResponseField>

<ResponseField name="data" type="object">
  <Expandable title="data fields">
    <ResponseField name="data.cibil_score" type="integer">
      The applicant's CIBIL score, ranging from 300 to 900.
    </ResponseField>
    <ResponseField name="data.currentCredit" type="number">
      Total current credit exposure across all accounts.
    </ResponseField>
    <ResponseField name="data.creditUsed" type="number">
      Total credit utilised across all active accounts.
    </ResponseField>
    <ResponseField name="data.obligate_amount" type="number">
      Sum of all active EMI amounts across open credit accounts. Used as the monthly obligation figure in FOIR calculations.
    </ResponseField>
    <ResponseField name="data.reportUrl" type="string">
      URL to the full CIBIL report PDF generated by the bureau.
    </ResponseField>
    <ResponseField name="data.OldestCreditAccountPeriod" type="string">
      Age of the oldest credit account in the bureau report.
    </ResponseField>
    <ResponseField name="data.Inquires" type="integer">
      Total number of enquiries recorded on the credit report.
    </ResponseField>
    <ResponseField name="data.OnTimePaymentHistory" type="string">
      Percentage or descriptor of on-time payment history.
    </ResponseField>
    <ResponseField name="data.CreditCardUtilization" type="string">
      Credit card utilisation percentage.
    </ResponseField>
    <ResponseField name="data.accounts" type="array">
      Array of credit account records. Each account includes fields such as `account_number`, `member_name`, `sanctioned_amount`, `current_balance`, `emi_amount`, `repayment_tenure`, `rate_of_interest`, `account_status`, `date_opened`, and `date_closed`.
    </ResponseField>
    <ResponseField name="data.enquiries" type="array">
      Array of recent credit enquiry records. Each enquiry includes `member_name`, `date`, and `purpose`.
    </ResponseField>
  </Expandable>
</ResponseField>

## Upload CIBIL PDF for AI Extraction

<ParamField path="POST /api/upload-cibil-pdf" type="endpoint" />

Upload an existing CIBIL report PDF when you already have a bureau-issued document. The platform extracts the text from the PDF, cleans it, and stores the raw content for downstream processing. The file field must be named `pdf` in the multipart form.

<Note>
  PDF parsing extracts text at upload time and stores it as a pending record. Ensure you upload a digitally generated PDF — scanned image PDFs will not yield usable text.
</Note>

### Request

```bash
curl -X POST "https://your-domain.com/api/upload-cibil-pdf" \
  -H "Authorization: Bearer {your_token}" \
  -H "Accept: application/json" \
  -F "loan_id=1" \
  -F "pdf=@/path/to/cibil-report.pdf"
```

### Parameters

<ParamField body="loan_id" type="integer" required>
  The ID of the loan to associate the uploaded CIBIL report with.
</ParamField>

<ParamField body="pdf" type="file" required>
  The CIBIL report PDF file. Must be a valid PDF (`application/pdf`). Maximum file size: 20 MB.
</ParamField>

### Response

```json
{
  "status": true,
  "message": "PDF text extracted successfully.",
  "data": {
    "text": "CIBIL REPORT\nBorrower Name: JOHN DOE\nCredit Score: 742 ...",
    "textLength": 14230
  }
}
```

<ResponseField name="data.text" type="string">
  The cleaned extracted text from the PDF, with page headers, URLs, and repeated whitespace removed.
</ResponseField>

<ResponseField name="data.textLength" type="integer">
  Character count of the extracted text. Use this to validate that meaningful content was extracted.
</ResponseField>

## Save CIBIL Data Manually

<ParamField path="POST /api/save-cibil-data" type="endpoint" />

Use this endpoint to manually save CIBIL-related loan data when you have obtained credit account information from an external source or through your own bureau integration. This is distinct from the live-fetch endpoint — it creates a credit data record directly from the values you supply, and also updates the `appraised_obligations` field on the eligibility report summary.

### Request

```bash
curl -X POST "https://your-domain.com/api/save-cibil-data" \
  -H "Authorization: Bearer {your_token}" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{
    "loan_id": 1,
    "bank_id": 3,
    "loan_account_no": "HDFC00123456",
    "loan_amount": 500000,
    "outstanding_amount": 120000,
    "emi_amount": 9500,
    "obligate_amount": 18000,
    "tenure": 60,
    "tenure_left": 24,
    "overdue": 0,
    "loan_type_id": 2,
    "cibil_status_id": 1,
    "account_type_id": 1
  }'
```

### Parameters

<ParamField body="loan_id" type="integer" required>
  The ID of the loan to attach this CIBIL record to.
</ParamField>

<ParamField body="bank_id" type="integer" required>
  The ID of the bank associated with the credit account. Use `GET /api/get-banks` (super_admin) to retrieve valid bank IDs.
</ParamField>

<ParamField body="loan_account_no" type="string" required>
  The credit account or loan account number as reported by the bureau.
</ParamField>

<ParamField body="loan_amount" type="number">
  The original sanctioned loan or credit limit amount.
</ParamField>

<ParamField body="outstanding_amount" type="number">
  The current outstanding balance on the account.
</ParamField>

<ParamField body="emi_amount" type="number">
  The monthly EMI obligation for this account.
</ParamField>

<ParamField body="obligate_amount" type="number">
  Total monthly obligation amount (sum of all active EMIs). This value is written to the eligibility report's `appraised_obligations` field.
</ParamField>

<ParamField body="tenure" type="integer">
  Original tenure of the loan in months.
</ParamField>

<ParamField body="tenure_left" type="integer">
  Remaining tenure in months.
</ParamField>

<ParamField body="overdue" type="number">
  Overdue amount, if any. Pass `0` if the account is current.
</ParamField>

<ParamField body="loan_type_id" type="integer">
  Loan type ID. Use `GET /api/get-loan-type` to retrieve valid values.
</ParamField>

<ParamField body="cibil_status_id" type="integer">
  CIBIL status classification ID. Use `GET /api/get-cibil-status` to retrieve valid values.
</ParamField>

<ParamField body="account_type_id" type="integer">
  Account type ID. Use `GET /api/get-account-type` to retrieve valid values.
</ParamField>

### Response

```json
{
  "status": true,
  "message": "Save successfully",
  "data": {
    "id": 14,
    "loan_id": 1,
    "bank_id": 3,
    "loan_account_no": "HDFC00123456",
    "obligate_amount": 18000,
    "created_at": "2024-03-01T10:22:00.000000Z"
  }
}
```
