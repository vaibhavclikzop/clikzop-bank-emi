---

Income Tax Return (ITR) data provides verified income figures used in loan eligibility calculations. Clikzop Bank EMI fetches ITR data directly from the Income Tax portal using the applicant's credentials. For salaried applicants, the platform extracts salary income, tax paid, refund amounts, and filing history. For business or self-employed applicants, it retrieves a full P&L and balance sheet spanning multiple assessment years, including gross profit, turnover, EBITDA, and capital structure. Both flows automatically seed the eligibility engine with the relevant financial year entries.

---

## Fetch Salaried ITR Details

<ParamField path="POST /api/get-salaried-itr-details" type="endpoint" />

Fetch ITR data for a salaried loan applicant by authenticating with their Income Tax portal credentials. The platform retrieves the applicant's filing history, income breakdown, outstanding demands, and refund status across all available assessment years, then stores the data against the loan and seeds the eligibility engine automatically.

<Warning>
  This endpoint uses the applicant's Income Tax portal username and password to authenticate with the Income Tax portal. Ensure this data is collected via a secure, consent-based flow within your application.
</Warning>

### Request

```bash
curl -X POST "https://your-domain.com/api/get-salaried-itr-details" \
  -H "Authorization: Bearer {your_token}" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_id": 42,
    "loan_id": 1,
    "loan_applicant_id": 7,
    "username": "ABCDE1234F",
    "password": "applicant_it_portal_password"
  }'
```

### Parameters

<ParamField body="customer_id" type="integer" required>
  The ID of the customer whose ITR data you are fetching.
</ParamField>

<ParamField body="loan_id" type="integer" required>
  The ID of the loan to associate the ITR data with.
</ParamField>

<ParamField body="loan_applicant_id" type="integer" required>
  The ID of the loan applicant record. Use this to differentiate primary applicants from co-applicants.
</ParamField>

<ParamField body="username" type="string" required>
  The applicant's Income Tax portal username (typically their PAN in uppercase).
</ParamField>

<ParamField body="password" type="string" required>
  The applicant's Income Tax portal password.
</ParamField>

### Response Fields

<ResponseField name="status" type="boolean">
  `true` on success.
</ResponseField>

<ResponseField name="data" type="object">
  <Expandable title="data fields">
    <ResponseField name="data.profileData" type="object">
      The applicant's ITR profile. Key fields include:
      - `pan_no` — PAN number
      - `name` — Name as per PAN records
      - `dob` — Date of birth
      - `aadhaar` — Aadhaar number (masked)
      - `email`, `mobile` — Contact details
      - `residential_status` — Residential tax status
      - `city`, `state_code`, `pin_code` — Address fields
      - `pdfDownloadLink`, `excelDownloadLink` — Report download URLs
    </ResponseField>
    <ResponseField name="data.filingData" type="array">
      Array of annual filing records. Each entry contains:
      - `financial_year` — e.g., `"2023-24"`
      - `assessment_year` — e.g., `"2024-25"`
      - `form_name` — ITR form type (ITR-1, ITR-2, etc.)
      - `filing_date` — Date of filing
      - `salary` — Gross salary income for the year
      - `house_property` — Income from house property
      - `other_sources` — Income from other sources
      - `capital_gains` — Capital gains
      - `taxes_paid` — Total taxes paid
      - `refund` — Refund amount, if any
      - `net_tax_liability` — Net tax liability
      - `immovable_assets`, `movable_assets`, `financial_assets` — Asset values
      - `total_liabilities` — Total declared liabilities
      - `delay`, `default`, `revised`, `late_fee` — Boolean compliance flags
    </ResponseField>
    <ResponseField name="data.filingHistory" type="array">
      Historical filing records including `assessment_year`, `form`, `status`, `date`, and `downloadLink`.
    </ResponseField>
    <ResponseField name="data.outstandingDemand" type="array">
      Array of outstanding tax demand records, each with `assessmentYear`, `outstandingDemandAmount`, `sectionCode`, and `dateOfService`.
    </ResponseField>
  </Expandable>
</ResponseField>

## Fetch Business ITR Details

<ParamField path="POST /api/get-business-itr-details" type="endpoint" />

Fetch ITR data for a business or self-employed loan applicant. In addition to the income and filing data retrieved for salaried applicants, this endpoint also pulls a full financial statement for each assessment year — including P&L figures, balance sheet components, and EBITDA.

<Note>
  Business ITR data is stored per financial year and linked to the loan applicant, enabling multi-year analysis. Each year's data feeds into the eligibility engine automatically.
</Note>

### Request

```bash
curl -X POST "https://your-domain.com/api/get-business-itr-details" \
  -H "Authorization: Bearer {your_token}" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{
    "customer_id": 42,
    "loan_id": 1,
    "username": "ABCDE1234F",
    "password": "applicant_it_portal_password"
  }'
```

### Parameters

<ParamField body="customer_id" type="integer" required>
  The ID of the customer whose business ITR data you are fetching.
</ParamField>

<ParamField body="loan_id" type="integer" required>
  The ID of the loan to associate the business ITR data with.
</ParamField>

<ParamField body="loan_applicant_id" type="integer">
  The ID of the loan applicant record. Provide this to associate the ITR data with a specific applicant on the loan (for example, a co-applicant).
</ParamField>

<ParamField body="username" type="string" required>
  The applicant's Income Tax portal username (typically their PAN in uppercase).
</ParamField>

<ParamField body="password" type="string" required>
  The applicant's Income Tax portal password.
</ParamField>

## Save Vanilla Report Year

<ParamField path="POST /api/save-vanilla-year" type="endpoint" />

Manually add a financial year entry to the eligibility report for a loan. This endpoint is ordinarily called automatically when ITR data is fetched, but you can use it to seed the eligibility engine with custom financial year data when working with externally sourced figures.

<Warning>
  This endpoint is currently non-operational in the platform (`"This api not working please connect to developer."`). ITR fetch endpoints (`get-salaried-itr-details`, `get-business-itr-details`) seed the eligibility engine automatically. Use those flows instead.
</Warning>

### Request

```bash
curl -X POST "https://your-domain.com/api/save-vanilla-year" \
  -H "Authorization: Bearer {your_token}" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{
    "loan_id": 1,
    "customer_id": 42,
    "financial_year": "2023-24",
    "turn_over": 2400000,
    "gross_profit": 480000
  }'
```

### Parameters

<ParamField body="loan_id" type="integer" required>
  The ID of the loan to add the financial year entry for.
</ParamField>

<ParamField body="customer_id" type="integer" required>
  The ID of the customer linked to the loan.
</ParamField>

<ParamField body="financial_year" type="string" required>
  The financial year string, e.g., `"2023-24"`.
</ParamField>

<ParamField body="turn_over" type="number" required>
  Annual turnover for the year.
</ParamField>

<ParamField body="gross_profit" type="number" required>
  Gross profit for the year.
</ParamField>
